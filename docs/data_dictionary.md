# Phase 2 Data Dictionary

This dictionary describes the nine synthetic e-commerce CSV files generated by
OmniPulse AI. A **primary key** uniquely identifies one row. A **foreign key**
links a row to a row in another dataset. Dates use `YYYY-MM-DD`; timestamps use
ISO 8601 format; money is recorded in US dollars and rounded to two decimals.

## `customers.csv`

One row represents one registered customer.

| Column | Meaning |
| --- | --- |
| `customer_id` | Primary key, such as `CUST-000001`. |
| `first_name` | Customer's given name. |
| `last_name` | Customer's family name. |
| `email` | Unique synthetic email address. All addresses use `example.com`. |
| `phone` | Synthetic US phone number. It is not a real contact number. |
| `gender` | Self-described gender or `Prefer not to say`. |
| `date_of_birth` | Customer's birth date. Generated customers are adults at signup. |
| `signup_date` | Date the customer created an account. |
| `city` | Customer's home city. |
| `state` | Two-letter US state abbreviation. |
| `country` | Customer's country; currently `United States`. |
| `postal_code` | Postal code associated with the city. |
| `customer_segment` | Business grouping: `New`, `Regular`, `Loyal`, or `VIP`. |
| `acquisition_channel` | How the business originally acquired the customer. |

## `products.csv`

One row represents one item offered in the product catalog.

| Column | Meaning |
| --- | --- |
| `product_id` | Primary key, such as `PROD-00001`. |
| `product_name` | Recruiter-readable synthetic product name. |
| `category` | Broad merchandise group, such as `Electronics`. |
| `subcategory` | More specific group, such as `Headphones`. |
| `brand` | Synthetic brand that makes the product. |
| `unit_price` | Normal selling price for one unit. |
| `cost_price` | Business cost for one unit; it does not exceed `unit_price`. |
| `launch_date` | Date the product entered the catalog. |
| `is_active` | `True` when the product is currently active in the catalog. |

## `orders.csv`

One row represents one customer order. Product-level details live in
`order_items.csv`.

| Column | Meaning |
| --- | --- |
| `order_id` | Primary key, such as `ORD-0000001`. |
| `customer_id` | Foreign key to the customer who placed the order. |
| `order_date` | Date the order was placed; never before customer signup. |
| `order_status` | Current stage: `Delivered`, `Shipped`, `Processing`, `Cancelled`, or `Returned`. |
| `shipping_city` | Destination city captured when the order was placed. |
| `shipping_state` | Destination state captured when the order was placed. |
| `shipping_country` | Destination country captured when the order was placed. |
| `shipping_cost` | Delivery charge; qualifying orders receive free shipping. |
| `discount_amount` | Sum of discounts across this order's item rows. |
| `tax_amount` | Tax calculated on the item total after discounts. |
| `order_total` | Item totals after discounts, plus shipping and tax. |

## `order_items.csv`

One row represents one distinct product line inside an order.

| Column | Meaning |
| --- | --- |
| `order_item_id` | Primary key, such as `ITEM-00000001`. |
| `order_id` | Foreign key to the containing order. |
| `product_id` | Foreign key to the purchased product. |
| `quantity` | Number of units purchased on this line. |
| `unit_price` | Selling price per unit at purchase time. |
| `discount_amount` | Discount applied to this entire line. |
| `line_total` | `quantity × unit_price − discount_amount`. |

## `payments.csv`

One row represents the payment attempt associated with an order.

| Column | Meaning |
| --- | --- |
| `payment_id` | Primary key, such as `PAY-0000001`. |
| `order_id` | Foreign key to the paid order. |
| `payment_date` | Date the payment was attempted. |
| `payment_method` | Method such as credit card, PayPal, or digital wallet. |
| `payment_status` | `Successful`, `Pending`, `Failed`, `Cancelled`, or `Refunded`. |
| `amount` | Payment amount, matching the order total. |

## `reviews.csv`

One row represents a customer's review of a product they ordered. Reviews are
normally produced for delivered or returned orders.

| Column | Meaning |
| --- | --- |
| `review_id` | Primary key, such as `REV-0000001`. |
| `order_id` | Foreign key to the reviewed purchase. |
| `product_id` | Foreign key to a product line in that order. |
| `customer_id` | Foreign key to the customer who placed the order. |
| `rating` | Whole-number score from 1 (lowest) to 5 (highest). |
| `review_title` | Short summary based on the rating. |
| `review_text` | Synthetic written feedback based on the rating. |
| `review_date` | Date of review; never earlier than the order date. |

## `inventory.csv`

One row represents the stock position for one product in one warehouse. A
product can therefore have several inventory rows.

| Column | Meaning |
| --- | --- |
| `inventory_id` | Primary key, such as `INV-0000001`. |
| `product_id` | Foreign key to the stocked product. |
| `warehouse_id` | Warehouse code: East, Central, or West. |
| `stock_quantity` | Units currently available; always zero or greater. |
| `reorder_level` | Quantity at which replenishment should be considered. |
| `last_updated` | Timestamp when this synthetic stock snapshot was recorded. |

## `marketing_campaigns.csv`

One row represents one marketing campaign and its aggregate funnel results.

| Column | Meaning |
| --- | --- |
| `campaign_id` | Primary key, such as `CAMP-0001`. |
| `campaign_name` | Human-readable campaign label. |
| `channel` | Delivery channel, such as email, search, or social media. |
| `start_date` | First date of the campaign. |
| `end_date` | Last date of the campaign. |
| `budget` | Planned campaign spend in US dollars. |
| `target_segment` | Customer segment the campaign aims to reach. |
| `impressions` | Number of times campaign content was displayed. |
| `clicks` | Number of clicks; never greater than impressions. |
| `conversions` | Desired actions; never greater than clicks. |

## `clickstream_events.csv`

One row represents one action during a website session. These high-volume event
rows describe behavior rather than a finalized business transaction.

| Column | Meaning |
| --- | --- |
| `event_id` | Primary key, such as `EVT-000000001`. |
| `session_id` | Groups ordered events from one browsing visit. |
| `customer_id` | Optional foreign key. Blank means the visitor was anonymous. |
| `event_timestamp` | Exact date and time of the event. |
| `event_type` | Funnel action: page view, product view, cart, checkout, or purchase. |
| `page_type` | Type of page on which the action occurred. |
| `product_id` | Optional foreign key. Blank when the event is not product-specific. |
| `device_type` | `Desktop`, `Mobile`, or `Tablet`. |
| `traffic_source` | Channel that brought the visitor to the site. |

## Intentional realism

Blank clickstream customer and product IDs are intentional and are not invalid
foreign keys. Anonymous visitors do not have customer IDs, while home, cart,
and checkout pages do not always refer to one product. A stock quantity of zero
is also valid: it represents an out-of-stock product at that warehouse.
